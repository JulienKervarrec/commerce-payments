# Chapitre 13 -- Limites et perimetre de ce parcours

Ce parcours couvre l architecture centrale du protocole Commerce Payments tel qu il existe dans le depot base/commerce-payments a la date du clone : le contrat AuthCaptureEscrow et son cycle de vie complet (authorize, capture, charge, void, reclaim, refund), l escrow TokenStore deploye a la demande par operateur, l abstraction TokenCollector et ses cinq implementations concretes, ainsi que le modele de frais borne cryptographiquement par le payeur.

Sont volontairement laisses hors champ : la suite de tests complete (test/), qui constitue neanmoins une source precieuse de scenarios limites pour qui veut approfondir ; les scripts de deploiement (script/Deploy.s.sol) ; le detail exhaustif des dependances externes que ce protocole compose sans les reimplementer -- Permit2 d Uniswap, SpendPermissionManager et MagicSpend de Base, Multicall3 -- documentees chacune dans leurs propres depots ; les adresses de deploiement officielles sur Base Mainnet et Base Sepolia, qui figurent dans le README du depot et evoluent a chaque nouvelle version ; et les rapports d audit externes (Spearbit, Coinbase Protocol Security), qui apportent une verification independante que ce parcours ne cherche pas a remplacer.

L objectif reste le meme que pour les parcours precedents de cette bibliotheque : donner une comprehension solide et verifiee du mecanisme central -- ici, comment un protocole d escrow minimaliste et agnostique du mode d autorisation peut reproduire le flux authorize/capture du commerce traditionnel entierement on-chain, avec des garanties cryptographiques opposables a l operateur des la signature initiale du payeur -- sans pretendre couvrir l integralite de l ecosysteme commerce-payments.
